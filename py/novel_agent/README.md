# novel_agent — 本地 AI 写小说服务（Ollama + Qwen2.5）

局域网内另一台电脑也能用的"大纲 → 逐章写小说"自动化服务。

## 一、启动

双击 `start.bat`（或在命令行执行）：

```
cd D:\CODE\Python\test-data-backup\py\novel_agent
python main.py
```

前置条件：Ollama 正在运行（任务栏托盘图标存在即可），模型 `mynovel:latest` 已安装。

- 服务地址（本机）：`http://127.0.0.1:8000`
- 局域网访问：`http://<本机IP>:8000`（如 `http://192.168.1.100:8000`）
  - 查看本机 IP：命令行执行 `ipconfig`，找"IPv4 地址"
  - 需关闭 Windows 防火墙对该端口的拦截，或放行 Python（首次局域网访问会弹防火墙提示，勾选允许）

## 二、页面操作流程

1. 浏览器打开服务地址，进入控制台
2. **选模型**：页面顶部下拉框可切换写作模型（列表来自 Ollama 已安装模型），切换立即生效并自动写入 config.json
3. **生成大纲**：填题材/风格/目标字数/每章字数 → 提交（约 4~30 分钟，视大纲规模）
4. **开始写作**：选择生成好的大纲 → 开始逐章写正文（每章 2000 字约 30~50 分钟）
5. 写作中可**暂停 / 继续 / 停止**；每章写完后可**单章重写**
6. **下载全本**：合并后的 Markdown 全文
7. **任务恢复**：网页关闭/刷新后，顶部"最近任务"下拉可找回之前的任务（自动记住最近一次）；服务未重启时能恢复实时状态。服务重启后任务列表清空，但已写入的章节与进度文件仍保留，可断点续写

## 三、API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 服务与模型状态 |
| POST | `/api/jobs` | 创建任务 `{type: outline/novel/chapter}` |
| GET | `/api/jobs/{id}` | 任务状态与日志 |
| POST | `/api/jobs/{id}/action` | `{action: pause/resume/stop}` |
| GET | `/api/books` | 书籍列表 |
| GET | `/api/books/{书名}/chapters/{n}` | 读取某一章 |
| GET | `/api/books/{书名}/outline` | 读取大纲 |
| GET | `/api/books/{书名}/download` | 下载全本 |

## 四、配置（config.json）

| 键 | 默认 | 说明 |
|---|---|---|
| model | mynovel:latest | 写作模型 |
| chapter_chars | 2000 | 每章目标字数 |
| num_predict | 2048 | 单次生成上限（token） |
| outline_predict | 2048 | 大纲生成上限 |
| num_ctx | 16384 | 上下文长度 |
| port | 8000 | 服务端口 |
| password | "" | **局域网开放前建议设置口令**，留空则免密 |
| books_dir | books | 作品输出目录 |

## 五、作品文件结构

```
books/书名/
├── 大纲.json        结构化大纲（可手工编辑后重新开始写作）
├── 大纲.md          人读版大纲
├── 剧情流水.md      已写章节的剧情摘要（供后续章节保持连贯）
├── progress.json    进度（断点续写依据）
└── 章节/
    ├── 001_第一章标题.md
    └── ...
```

## 七、本机性能约束（必须了解）

- 纯 CPU 推理，实测约 **0.6~1.2 token/秒**，内存紧张（16GB 机器，模型占 ~4.6GB）
- **每章 2000 字 ≈ 30~50 分钟**，一本 30 章的小说 ≈ 15~25 小时
- 建议：晚间挂机写作；中途可暂停；进度会自动保存，重启服务后可断点续写
- 大纲 JSON 已做三重容错（扁平结构 + 宽容解析 + 自动修复），一般不会失败
