# PDF 转本地多人播客

## 职责分工（关键）

- **本技能（AI 执行）**：读 PDF → 提炼主线/知识点 → 写多角色播客脚本（`.md`，台词按规范标注音色，Python 脚本可直接解析）。
- **scripts/（Python 执行）**：`parse_script.py` 解析脚本 → `generate_audio.py` 调本地 CosyVoice 逐块生成 → `merge_audio.py` 顺序合并 + 可选 BGM + 响度统一。
- 用户本地运行 scripts，AI 不代跑生成（也可代跑，取决于用户要求）。

## 工作流总览

1. **完整读取 PDF** — `Read` 读全内容，不跳读。
2. **内容与角色分析** — 提炼主线、知识点清单（零删减）、角色表（身份/性格 → 分配音色）。
3. **规划时长与段落（本地实测口径）** — 本地 CosyVoice 中文语速约 4.7 字/秒；含 400ms 块间静音整体约 **100 字 ≈ 22 秒**。目标 30 分钟 ≈ **8100–8300 字**；20 分钟 ≈ 5500 字；10 分钟 ≈ 2700 字。块数按"每块 30–120 字"自然形成（30 分钟通常 130–145 块）。**不要**按"每段 110 秒、16 段"规划——那是在线 TTS 通道的口径，本地语速更快。
4. **撰写标注脚本** — 按 `assets/播客脚本模板.md` 写脚本，每行台词必须以 `[音色名] ` 开头（见 `references/script-format.md` 规范，必须可解析）。
5. **交付脚本给用户** — 用户用 `scripts/` 本地生成合并，或按用户要求代跑。

## 硬性规则

- **音色名只能取自已定音色表**（`references/script-format.md` 第2节，默认 6 音色：啊乐=通用男声、桃子=通用女声、郭靖=老年男声、球球=老年女声、萌萌=儿童男声、雪花=儿童女声）。脚本中不得出现音色表之外的名字。
- **每条台词独占一行**，格式 `[音色名] 台词内容`；段标题用 `【第N段 标题】`；连续同角色多句合并为一块（避免碎块太多）。
- **同段内角色切换 = 新块**：相邻两块若音色相同且无段标题分隔，可合并为一块；解析脚本按行处理，重复音色行自然连续。
- **文本适配 TTS**：数字读法写汉字（"120"→"一百二十"）、拼音/字母内容必须汉字谐音化（沿用 pdf-to-podcast 的对照表）、生僻字注音、口语化改写，避免本地 TTS 误读。
- **成品时长校验（必做）**：合并完成后用 ffprobe 核对时长，偏差超目标 ±10% 时必须修正——按实测口径（100 字 ≈ 22 秒）增删脚本对应段落，重新生成变更块后再合并；不得以"差不多"交付。
- **音色分配**：旁白/主播/通用解说 → 啊乐（通用男声）或桃子（通用女声）；阿公/老年男性 → 郭靖（老年男声）；阿婆/老年女性 → 球球（老年女声）；男童角色 → 萌萌（儿童男声）；女童角色 → 雪花（儿童女声）；用户可另行指定。
- **交付**：脚本 `.md` 一份交付；脚本文件头写入音色表与参考音频路径，保证脚本自包含。

## 用户可调选项

- 角色与音色分配（默认 6 音色，可扩展音色表）
- 目标时长（默认 30 分钟）
- 台词块粒度（默认"连续同角色一段一块"，可切更细）
- 是否加 BGM、响度目标（默认 -16 LUFS）
