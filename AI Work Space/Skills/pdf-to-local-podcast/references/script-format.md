# 播客脚本标注格式规范（解析器契约）

> 本规范是 **AI 写脚本** 与 **Python 解析脚本** 之间的唯一契约。AI 产出的播客脚本必须严格遵守本节语法；`parse_script.py` 按本节规则解析。任何一方偏离本规范都会导致解析失败或漏词。

## 1. 文件格式

- 脚本为 UTF-8 编码的 `.md` 文本文件。
- 脚本由「头部信息」+「台词块序列」两部分组成，之间以一行 `---` 分隔。

```
【播客信息】
书名：xxx
目标时长：30分钟
音色表：见文件头下方（或引用的音色表文件）
---
[啊乐] 小朋友们好，欢迎收听《xxx》！
[雪花] 哇，太好啦！
```

- `【播客信息】` 及其后的键值行（`键：值`）为头部，解析器只读取，不参与生成。
- 头部之后（从 `---` 下一行开始）才是台词块序列。

**角色分配规则（写脚本时按此选音色）**：

- 旁白 / 主播 / 通用解说 → `啊乐`（通用男声）或 `桃子`（通用女声）
- 阿公、爷爷、老年男性角色 → `郭靖`（老年男声）
- 阿婆、奶奶、老年女性角色 → `球球`（老年女声）
- 男童角色 → `萌萌`（儿童男声）
- 女童角色 → `雪花`（儿童女声）

- 音色名与文件名的对应关系由 `scripts/voices.py` 内置（`VOICE_TABLE`，本地 CLI 与 web 共用同一音色表），AI 无需在脚本里重复写文件路径。
- 如需新增音色：往 `scripts/voices.py` 的 `VOICE_TABLE` 加一条，并同步 `web/data/voices.json`，脚本里即可使用新音色名。

## 3. 台词块语法（解析器真正读取的部分）

| 行类型 | 语法 | 解析行为 |
|---|---|---|
| 段标题 | `【第N段 标题】` | 跳过（不生成音频），仅作结构提示 |
| 台词块 | `[音色名] 台词内容` | 生成 1 个音频块；音色名必须在音色表内 |
| 纯注释 | 以 `#` 开头的行 | 跳过 |
| 空行 | （空白） | 跳过 |
| 其他内容 | 不符合上述任一规则的行 | 警告并跳过（AI 应避免产生这种行） |

**块粒度约定**：

- 同一角色连续多句台词应写在同一行（用句号连接），或写成多行但保持同一音色——解析器按"连续同音色行合并为一个块"处理。
- 一个块生成 1 个 wav（`001.wav`、`002.wav`…按块顺序编号）。
- 建议每个块 30–120 字（约 10–40 秒），块太短（<5 字）会碎、太长（>200 字）单次生成易超时。

### 时长规划（本地 CosyVoice 实测口径，写脚本前必读）

本地合成语速比在线 TTS 快，**不要沿用"每段 110 秒、450–520 字、30 分钟 16 段"的在线口径**。实测换算（2026-10-12《清平乐·村居》：6650 字 / 112 块 → 成品 1455 秒）：

- 纯语音速率 ≈ 4.7 字/秒；含块间静音（默认 400ms/块）整体约 **100 字 ≈ 22 秒**。
- 目标时长 → 脚本字数：30 分钟 ≈ **8100–8300 字**；20 分钟 ≈ 5500 字；10 分钟 ≈ 2700 字。
- 字数决定了自然块数（每块 30–120 字），30 分钟通常 **130–145 块**。
- 估算公式：成品秒数 ≈ 字数 × 0.212 + 块数 × 0.4。
- 宁可略多写 5%（每块 60–80 字更稳），也不要写少了；成片偏长可由合并参数收，偏短只能重生成。

### 示例

```
【第1段 开场】

[啊乐] 小朋友们好，欢迎收听《数学历险记》！我是主播阿乐叔叔。
[桃子] 我是桃子姐姐。今天我们要去数字王国探险。
[萌萌] 出发！出发！
[雪花] 等等我呀！
```

解析结果：4 个块 → `001.wav`(啊乐) → `002.wav`(桃子) → `003.wav`(萌萌) → `004.wav`(雪花)。

## 4. 文本适配 TTS 规则（AI 写台词时必须遵守）

本地 CosyVoice 按字面读，**不会智能纠错**，以下内容必须预先改写，否则会读错、误导小朋友：

1. **数字一律写汉字读音**：`120` → `一百二十`；`3.14` → `三点一四`；`2026年` → `二零二六年`。
2. **拼音/字母一律汉字谐音化**（沿用 pdf-to-podcast 对照表）：
   - 声母/韵母：a→啊、b→波、p→泼、m→摸、f→佛、d→得、t→特、n→讷、l→勒、g→哥、k→科、h→喝、j→基、q→期、x→西、zh→知、ch→吃、sh→诗、z→资、c→雌、s→思、y→衣、w→乌、o→喔、e→鹅、i→衣、u→乌、ü→迂、ai→爱、ei→诶、ui→威、ao→熬、ou→欧、iu→优、an→安、en→恩、in→因、un→温、ün→晕、ang→昂、eng→鞥、ing→英、ong→翁、er→儿
   - 拼读示例：b-a → "波-啊"；ba → "巴"
   - 声调描述：一声平 / 二声扬 / 三声拐弯 / 四声降
3. **英文单词/缩写**：尽量译为中文；必须保留的（如歌曲名）用中文读音注出。
4. **生僻字/多音字**：用常见同音字或括号注音，如 `龘（读达）`。
5. **标点口语化**：避免长句逗号堆叠；感叹句可用"呀、啊、啦、哦"等语气词。

## 5. 解析产物（任务清单 JSON）

`parse_script.py <脚本.md> [--out 任务清单.json]` 输出：

```json
{
  "book": "数学历险记",
  "duration_min": 30,
  "blocks": [
    {"idx": 1, "voice": "啊乐", "text": "小朋友们好，欢迎收听《数学历险记》！我是主播阿乐叔叔。"},
    {"idx": 2, "voice": "桃子", "text": "我是桃子姐姐。今天我们要去数字王国探险。"}
  ]
}
```

- `blocks` 顺序即音频拼接顺序（001、002…）。
- 该 JSON 是 `generate_audio.py` 的输入，也可人工编辑（如临时改某块文本/音色后重新生成）。
