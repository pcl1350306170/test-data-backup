# WSL 与 MySQL 自动备份 · 使用与还原说明

> 适用环境：Windows + WSL2（Ubuntu）+ MySQL 8.4
> 更新日期：2026-09-11

---

## 一、备份体系总览

| 备份对象 | 频率 | 触发方式 | 备份位置 | 保留份数 |
|---|---|---|---|---|
| MySQL 全库（WSL 内） | 每周日 02:00 | WSL cron | WSL 内 `/root/mysql-backup/` | 5 份 |
| WSL 整机镜像（Windows） | 每月 1 号 03:00 | Windows 任务计划 | `D:\FILES\IMG\AI自定义\WSL` | 2 份 |

- **MySQL 备份**：`mysqldump --all-databases` 全库导出 + gzip 压缩。
- **WSL 整机备份**：`wsl --export` 导出整个发行版为 tar 镜像，可用 `wsl --import` 完整恢复（含系统、软件、MySQL 数据、定时任务等全部状态）。
- 两套备份互相独立，恢复时也互不影响。

## 二、备份脚本

### 2.1 脚本一：MySQL 每周备份（在 WSL 内运行）

| 项目 | 内容 |
|---|---|
| 脚本文件 | `mysql_weekly_backup.sh`（本目录） |
| 已安装位置 | `/usr/local/bin/mysql_weekly_backup.sh` |
| 备份账号 | `dev_user / 123456` |
| 备份内容 | 全部数据库（含存储过程、触发器） |
| 备份目录 | `/root/mysql-backup/` |
| 日志 | `/root/mysql-backup/backup.log` |
| 定时 | 每周日 02:00（root 的 crontab） |
| 保留 | 自动保留最近 5 份，更早的自动删除 |

#### 日常使用命令（在 Windows PowerShell 里执行）

```powershell
# 手动运行一次备份
wsl -u root -e bash -lc '/usr/local/bin/mysql_weekly_backup.sh'

# 查看已有备份
wsl -u root -e bash -lc 'ls -lh /root/mysql-backup/'

# 查看最近日志
wsl -u root -e bash -lc 'tail -20 /root/mysql-backup/backup.log'

# 校验某个备份包是否完整（能解压出 SQL 即正常）
wsl -u root -e bash -lc 'zcat /root/mysql-backup/mysql-最新.sql.gz | head -5'
```

#### 重新安装 / 卸载定时任务

```powershell
# 重新注册 cron（每周日 02:00），脚本会先复制到 /usr/local/bin
wsl -u root -e bash -lc 'bash /mnt/d/CODE/Python/test-data-backup/AI\ Work\ Space/WSL/mysql_weekly_backup.sh --install'

# 查看当前 cron 配置
wsl -u root -e bash -lc 'crontab -l'

# 卸载 cron（进入编辑器删除 mysql_weekly_backup.sh 那一行后保存）
wsl -u root -e bash -lc 'crontab -e'
```

> 注意：`--install` 必须以 **root** 身份执行（`wsl -u root`），否则脚本复制不到 `/usr/local/bin`。
> 日志里的 `Using a password on the command line interface can be insecure` 是 mysqldump 的正常警告，可忽略。

#### 调整参数

编辑 `mysql_weekly_backup.sh` 顶部的变量后重新安装即可：

| 变量 | 说明 | 当前值 |
|---|---|---|
| `MYSQL_USER` / `MYSQL_PASSWORD` | MySQL 备份账号 | `dev_user` / `123456` |
| `BACKUP_DIR` | 备份目录 | `/root/mysql-backup` |
| `KEEP_COUNT` | 保留份数 | `5` |
| `CRON_LINE`（--install 内） | 定时表达式 | `0 2 * * 0`（每周日 02:00） |

### 2.2 脚本二：WSL 整机每月备份（在 Windows 运行）

| 项目 | 内容 |
|---|---|
| 脚本文件 | `wsl_monthly_backup.ps1`（本目录） |
| 备份方式 | `wsl --export` 导出 tar 镜像 |
| 备份目录 | `D:\FILES\IMG\AI自定义\WSL` |
| 日志 | `D:\FILES\IMG\AI自定义\WSL\backup.log` |
| 定时 | 每月 1 号 03:00（任务计划"WSL每月整机备份"） |
| 保留 | 自动保留最近 2 份，更早的自动删除 |

#### 日常使用命令（在 Windows PowerShell 里执行）

```powershell
# 手动运行一次备份
powershell -ExecutionPolicy Bypass -File "D:\CODE\Python\test-data-backup\AI Work Space\WSL\wsl_monthly_backup.ps1"

# 查看已有备份与日志
Get-ChildItem "D:\FILES\IMG\AI自定义\WSL"
Get-Content "D:\FILES\IMG\AI自定义\WSL\backup.log" -Tail 20
```

#### 注册 / 卸载定时任务

```powershell
# 注册任务计划（每月 1 号 03:00）
powershell -ExecutionPolicy Bypass -File "D:\CODE\Python\test-data-backup\AI Work Space\WSL\wsl_monthly_backup.ps1" -Install

# 查看任务计划状态
schtasks /Query /TN "WSL每月整机备份" /FO LIST

# 删除任务计划
schtasks /Delete /TN "WSL每月整机备份" /F
```

#### 脚本的两个已知处理（勿改动）

1. **中文路径兼容**：`wsl.exe --export` 不支持含中文的目标路径（会直接打印 usage 失败），所以脚本先导出到 `%TEMP%\wsl-backup-tmp`（纯 ASCII 临时路径），完成后再移动到 `D:\FILES\IMG\AI自定义\WSL`。移动过程需要时间（跨盘复制）。
2. **发行版名 NUL 清洗**：PowerShell 5.1 读取 `wsl.exe --list --quiet` 的输出时，UTF-16 解码会让每个字符后混入 NUL（`\0`），导致 `wsl --export` 识别不了发行版名。脚本已用 `-replace "`0", ""` 清洗。

## 三、还原备份

> ⚠️ 还原属于**覆盖性操作**，会丢失当前数据。执行前确认备份文件完好，并先导出当前状态保底。

### 3.1 还原 MySQL（在 WSL 内执行）

#### 全库还原

```bash
# 1. 查看有哪些备份，选最新的
wsl -u root -e bash -lc 'ls -lh /root/mysql-backup/'

# 2. 全库还原（会用备份覆盖当前所有数据库）
wsl -u root -e bash -lc 'zcat /root/mysql-backup/mysql-20260911-104528.sql.gz | mysql -u root -p'

# 3. 验证
wsl -u root -e bash -lc 'mysql -u root -p -e "SHOW DATABASES;"'
```

要点：
- 用 **MySQL root 账号**还原（全库备份含 mysql、sys 等系统库，`dev_user` 权限不足会中断报错）。
- 全库还原会覆盖**所有**数据库，备份时间点之后的新数据会丢失。

#### 只还原单个库

```bash
# 1. 解压备份
wsl -u root -e bash -lc 'gunzip -c /root/mysql-backup/mysql-最新.sql.gz > /tmp/mysql-full.sql'

# 2. 先建目标库（如 bizdb）
wsl -u root -e bash -lc 'mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS bizdb;"'

# 3. 从全库备份中提取该库的建表与数据段（编辑 /tmp/mysql-full.sql 找到
#    "Current Database: bizdb" 与 "USE bizdb" 附近内容，另存为 single.sql），再导入
wsl -u root -e bash -lc 'mysql -u root -p bizdb < /tmp/single.sql'
```

### 3.2 还原整个 WSL（在 Windows PowerShell 执行）

```powershell
# 0.（强烈建议）先把当前 WSL 导出一份，还原失败可退回
wsl --export Ubuntu "D:\FILES\IMG\AI自定义\WSL\before-restore.tar"

# 1. 删除现有 Ubuntu（⚠️ 清空当前 Ubuntu 的所有数据）
wsl --unregister Ubuntu

# 2. 从备份导入（D:\WSL\Ubuntu 是安装位置，可自定；用实际备份文件名替换）
wsl --import Ubuntu D:\WSL\Ubuntu "D:\FILES\IMG\AI自定义\WSL\wsl-Ubuntu-20260911-105237.tar" --version 2

# 3. 恢复默认登录用户（导入后默认变 root，恢复成日常用户 pcl13）
wsl --manage Ubuntu --set-default-user pcl13

# 4. 验证（应输出 pcl13；/root/mysql-backup 应回到备份时间点的状态）
wsl -d Ubuntu whoami
wsl -d Ubuntu ls /root/mysql-backup/
```

要点：
- 还原后 WSL 是**备份那一刻的完整状态**：系统、软件、MySQL 数据、cron 定时、脚本都回到那个时间点。
- 如果 `wsl --manage --set-default-user` 报不支持（WSL 版本较旧），改用备选方案：

```powershell
wsl -d Ubuntu -u root -e sh -c "echo -e '[user]\ndefault=pcl13' > /etc/wsl.conf"
wsl --terminate Ubuntu   # 重启 WSL 后生效
```

- 恢复后若需要重新装回备份脚本与定时任务，参照第二节重新执行 `--install` 即可（脚本文件在本目录，不受 WSL 还原影响）。

## 四、常见问题排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 周日 MySQL 备份没跑 | WSL 未运行（cron 只在 WSL 启动后生效） | 检查 VBS 自启文件是否存在；手动 `wsl -u root -e bash -lc '/usr/local/bin/mysql_weekly_backup.sh'` 跑一次 |
| 周备没跑且 WSL 在运行 | cron 服务未启动 | `wsl -u root -e bash -lc 'service cron status'`，未运行则 `service cron start` |
| 月备没跑 | 任务计划被删 / 登录方式问题 | `schtasks /Query /TN "WSL每月整机备份" /FO LIST`，缺失则重新 `-Install` |
| 手动运行脚本二报"导出失败" | 临时目录被清理 / 权限 | 查看 `D:\FILES\IMG\AI自定义\WSL\backup.log`，确认 `%TEMP%\wsl-backup-tmp` 可写 |
| 磁盘空间不足 | 备份文件累积 | 保留策略会自动清理；也可手动删除最旧文件 |
| 想验证备份能否用 | 恢复演练 | 按第三节步骤，把备份导入一个临时发行版/测试库验证 |
