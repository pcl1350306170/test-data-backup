# 病房 Web 开发辅助工具 - 功能与接口说明

## 概述

本插件通过浮动菜单提供 6 项功能，所有功能均通过 `fetch` 请求外部代理服务，**不调用当前页面所在服务的接口**。

- **外部接口基地址（apiBaseUrl）**：`http://192.168.18.228:28019`（可在插件设置页修改）
- **请求方式**：均为 `POST`，`Content-Type: application/json`

---

## 页面接口鉴权说明（callPageApi / callPageApiGet）

病房业务服务（`tdms`、`bnms`、`hpms` 等）采用 **Sa-Token（RuoYi-Vue-Plus 体系）** 鉴权，服务端**通过请求头 `Authorization` 中的 token 判断登录态**，而非 cookie。凡是通过 `callPageApi` / `callPageApiGet` 直接调用当前页面服务接口的功能（宣教分类添加、宣教添加、Mock 数据等），都必须携带以下请求头：

| 请求头 | 值 | 说明 |
|--------|-----|------|
| `Authorization` | `Bearer <JWT token>` | 登录令牌，缺失时服务端返回“登录已过期，请重新登录” |
| `clientid` | 如 `e5cd7e4891bf95d1d19206ce24a7b32e` | 客户端标识，部分接口校验 |

### 为什么需要插件手动附加 token

- 页面自身的业务请求由 **axios 拦截器**自动附加 `Authorization` 头，所以页面用着正常；
- 但插件使用**原生 `fetch`** 调用接口，绕过了页面 axios 拦截器，不会自动带 token；
- 因此 `callPageApi` / `callPageApiGet` 内部通过 `getPageAuthHeaders()` 主动读取并附加 token，否则会报“登录已过期”。

### token 获取逻辑（getPageAuthHeaders）

1. **按已知键名读取**：依次从 `localStorage` → `sessionStorage` → `cookie` 中查找键名 `Admin-Token`、`Login-Token`、`token`、`access_token`、`accessToken`、`Authorization`、`satoken`；
2. **兜底扫描**：若上述键名均未命中，扫描 `localStorage` / `sessionStorage` 中任意形如 JWT（`eyJ...`）的值；
3. **提取纯 token**：去掉可能的 JSON 引号包装，用正则提取纯 JWT 字符串，拼接为 `Bearer <token>`；
4. **clientid**：优先读存储中的 `clientid` / `clientId`，其次从 JWT payload 解析 `clientid` 字段。

> **前提**：调用这些功能前，当前页面必须处于**已登录**状态（token 已写入页面存储）。若控制台出现 `[Ward] 未能从页面存储中获取登录 token` 警告，说明未登录或 token 键名特殊，需检查页面存储或 Network 中正常请求的 `Authorization` 头格式，再调整 `TOKEN_KEYS`。

> **限制**：若 token 存放于 HttpOnly cookie，content script 无法读取；但此时页面 JS 同样无法将其放入 `Authorization` 头，故一般不存在该情况。

## 调用架构

```
Chrome 插件 (content.js)
        │
        │  fetch POST
        ▼
外部代理服务 (192.168.18.228:28019)
        │
        │  代理执行 SQL / 调用业务接口
        ▼
目标数据库 (YHDB) / 病房业务服务
```

插件本身不直接连接数据库或调用目标页面业务接口，所有操作均通过外部代理服务中转。

> 例外：宣教分类添加、宣教添加功能通过 `callPageApi` / `callPageApiGet` 通用函数直接调用当前页面所在服务的接口。
